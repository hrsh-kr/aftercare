Architecture

Five AWS tools. One job each.

The model only words a step. Code decides the rest.

  1. CustomerWhatsApp · simulated
  2. API Gatewayone front door
  3. Lambdaone function, 26 routes
  4. Four serviceseach does one thing
01

API Gateway + Lambda

Serves every page and API route.

Why
Stateless: a chat survives any restart.
Trade-off
Cold starts. A code change needs a rebuild.
checking…
02

Strands Agents

Words one manual step. Reads a vague reply.

Why
A small model on narrow jobs, timed by hooks.
Trade-off
Local model is slower, so rules do the rest.
checking…
03

OpenSearch

Finds the manual section. Spots repeat faults.

Why
Ranked search and time-window queries in one engine.
Trade-off
Heavier than a database. Keywords, not meaning.
checking…
04

Cedar

Decides who may view, reply, resolve.

Why
Rules as policy files. Each answer names its policy.
Trade-off
One more language to learn.
checking…
05

DynamoDB

One table: customers, chats, tickets, cases.

Why
Known access patterns. Fast, and an atomic ticket counter.
Trade-off
Queries are designed up front. Ad-hoc ones go to OpenSearch.
checking…

Never left to the model: safety, next step, two tries then a person, warranty dates, who sees what.

Runs locally, no account. Deploy path: Bedrock · OpenSearch Service · Verified Permissions · DynamoDB.
